# Coverage administration

Administrators open cobertura-gerenciar.html through Gerenciar cobertura. Profiles are verified by the existing authenticated shell; coverage_sources and coverage-files policies enforce active administrator writes server-side. Active sellers and partners read published metadata and geometries only. Original files are private to administrators. No privileged API keys in the client.

City records indicate municipal presence, not property-level feasibility. Original VERO cities can be overridden without changing the static source list. Static Desktop, Claro, Alcans and VERO bases each have a reversible activation switch, initially enabled. New maps supplement static bases. Optional replacement atomically disables only earlier managed maps for the same operator, city and UF; static bases stay unchanged.

Import limits: original 50 MB, decompressed KML 80 MB, 20,000 area features / 1 million vertices per KML. One city per import. KML coordinates only: polygons, holes and explicitly closed lines; points, descriptions, open lines and external network references never establish coverage. XML DTD/entities and NetworkLinks are rejected. The server validates geometry in bounded batches using PostGIS and repairs invalid exteriors while subtracting holes. Explicit blocked/restricted labels inherited from folders remain negative coverage. One empty or non-repairable area rejects the import instead of silently omitting it.

Original files and derived geometry chunks are kept in private Storage. The table contains metadata, bounds, checksums, timestamps and state. Drafts are not read by sellers or partners. Publication happens only from the preview dialog. A failed upload is cleaned up and its incomplete draft cannot publish. Spatial lookup downloads chunks intersecting the approximate CEP location; city search downloads polygons only when opening a map. Metadata refreshes after 15 seconds on subsequent searches. No heavy KMZ is downloaded by sales users.

Validation: PostgreSQL role tests deny seller writes and validation/publication; original bases remain active; atomic replacement tested in rolled-back transactions; invalid bow-tie repair tested. Browser preview tested city creation and draft preview/publication with isolated fixtures. Parser tests cover polygons, inherited restrictions, holes, closed/open lines, points, malformed coordinates and external XML/NetworkLinks. Node integration regression covers Itu original coverage, managed geometry, draft exclusion, city overrides, disabled bases, restricted areas and spatial lazy loading. No synthetic city/map records persisted in production. Authenticated real-user browser upload was not exercised.
